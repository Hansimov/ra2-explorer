# RA2 Explorer 架构

本文描述当前可执行实现的长期边界。具体版本号、快照哈希、某台电脑的资产数量和阶段性修复记录不属于架构契约。

## 运行形态

RA2 Explorer 有两种共用 React 界面的运行形态：

| 形态 | 数据入口 | 服务端 | 能力边界 |
| --- | --- | --- | --- |
| Windows 本地 Web 应用 | 用户的合法 RA2/YR 安装或 `.ra2pack` | 回环地址上的 FastAPI | 完整扫描、解析、地图、导出与派生缓存 |
| GitHub Pages 精简版 | 固定的单位与声音静态快照 | 无 | 在线浏览、搜索、模型、动画和声音预览 |

本地调用链：

```text
只读游戏目录
  → MIX/格式解析层
  → SQLite 索引与 RULES/ART/CSF 语义目录
  → FastAPI（127.0.0.1:46120）
  → React 浏览器界面
          ↘ .runtime\RA2MD-Ext 派生缓存
```

CLI 与 HTTP API 共用 `SourceLibrary`、`AssetReader`、格式解析器和语义目录，不维护第二套解析逻辑。本地生产包使用电脑已有的浏览器，不嵌入 Electron、Chromium 或 WebView；运行时不需要 Node。

Pages 不运行 Python、FastAPI 或 SQLite。构建阶段把允许公开的语义目录和派生媒体转换为只读文件，前端静态适配器实现相同的查询接口子集。

## 数据边界

- `.runtime\RA2MD` 是约定的可选游戏目录，只读；任何流程都不得运行其中的程序。
- `.runtime\RA2MD-Ext\index` 保存 SQLite，`artifacts` 保存预览、模型和转码媒体，`reference` 保存可重建参考数据，`packages` 与 `pages` 保存本地发行中间结果。
- 普通浏览直接读取松散文件或 MIX 区段，不永久复制每个成员。只有显式 `extract` 产生原始成员副本。
- 派生缓存键包含来源、扫描修订、资产 ID、渲染参数和解析器版本；来源重扫或算法修订后不会命中旧结果。
- 扫描器排除 `RA2MD-Ext`，防止派生结果被当成游戏输入。
- `.runtime`、`.secrets`、构建输出、游戏目录和 QA 产物不进入 Git。

真正参与语义解析的零售文件、覆盖顺序和按引用素材见 [游戏源输入](GAME_SOURCE_INPUTS.md)。

## 格式层

| 格式 | 当前能力 |
| --- | --- |
| MIX / MMX / YRO | 经典与 RA2/TS 哈希、Blowfish 索引、嵌套归档、按区段读取 |
| PAL / VPL | 256 色调色板、VPL 亮度层、网格预览和 VXL 着色 |
| SHP (TS/RA2) | 压缩 0–3、透明索引、逐帧预览、阴影配对和动画序列 |
| VXL / HVA | 体素列、部件与矩阵、八向组合、WebGL 三维场景和 HVA 时间轴 |
| TMP 及剧场扩展 | 菱形地块、深度与 extra 层、逐地块预览 |
| INI / CSF / TXT | 编码探测、结构解析、简繁本地化和全文检索 |
| MAP / MPR | 地图元数据、对象与路径点布局；尚非完整等距地表复刻 |
| WAV / AUD / IDX+BAG | 元信息、PCM/IMA/Westwood 解码、按片段播放和导出 |
| PCX | 受像素上限约束的 PNG 预览 |
| VQA / BIK | 索引与按需 FFmpeg 转码；FFmpeg 来自系统，不从游戏目录执行 |
| FNT 与未知条目 | 索引、检索和原始导出；FNT 暂无专用视图 |

解析器对归档范围、递归深度、条目数、文本大小、图像像素、体素数和媒体输出设置防御性上限。单项损坏形成可诊断错误；扫描的原子替换会保留上一版可用索引，避免半成品覆盖。

## 语义目录

### 单位

实体来自 RULES 的 `VehicleTypes`、`AircraftTypes`、`InfantryTypes` 和 `BuildingTypes`。规则节的 `Image`（缺省为实体 ID）选择 Techno ART 节；ART 再决定 VXL/SHP、剧场扩展、Cameo、炮塔、炮管、HVA 和动画图层。建筑并不总是单一 SHP：`TurretAnimIsVoxel` 可让 SHP 主体组合独立 VXL 炮塔与炮管，`BibShape` 则提供主体下方的地基层；卡片和详情预览都以相同锚点合成这些部件。海豚 `DLPH` 与巨型乌贼 `SQD` 在零售规则中都属于 `VehicleTypes` 且设置 `Naval=yes`，因此目录保持“载具”主类型，并用海军属性继续细分，不按外观改成人为类型。

`rulesmd.ini` 是尤里的复仇完整规则集；存在时以它作为当前版本输入，不与红警 2 的 `rules.ini` 做字段级合并。只有来源没有 `rulesmd.ini` 时才回退到 `rules.ini`，避免单位继承另一游戏版本的阵营或建造限制。

目录列出全部规则实体，不以“当前能否预览”作为隐藏条件。`Owner`、`AIBasePlanningSide`、`TechLevel`、`BuildLimit`、`Capturable`、`Civilian` 等字段共同计算单位用途和唯一显示归属；缺少可靠归属的对象进入“无阵营”，不会同时命中所有阵营。

武器关系从 `Primary`、`Secondary` 和精英槽位继续追踪到 Weapon、Projectile 与 Warhead。详情保留解析状态和关键规则，但不会把孤立开火闪光、命中特效或随机残骸冒充完整战斗动画。

### 动画

- 步兵 `Sequence` 和非 VXL Techno 的 ART 帧区间生成主体动作；帧内步长与八向朝向分别保存。
- 建筑 `Buildup` 生成建造序列；`ActiveAnim*`、`IdleAnim*` 是可同时存在的持续图层，生产、特殊动作、展开和舱门字段是按事件触发的状态序列，不会全部叠到默认外观上。
- 超级武器的 `SuperAnim`、`SuperAnimTwo`、`SuperAnimThree`、`SuperAnimFour` 分别表示未充能待机、启动/充能、充能就绪和发射后复位。四个状态互斥显示；用户选择某个阶段时，预览只把该阶段与建筑主体及其他兼容的持续图层合成。
- ART 的 `End` 通常是含尾帧编号；零售维修厂少数共享图像段把它作为帧数，解析器按同图像的正常/受损段结构识别该约定。`Reverse=yes` 会反向播放，未声明尾帧但后续受损段共用同一图像时以前一段边界截断。
- SHP 后半段若由规则或像素证据确定为阴影，会逐帧叠加而不是串行播放。
- 只有能够与当前主体可靠对齐的主体、建造和运行序列进入动画面板。武器、弹体、命中、`DeathWeapon` 与残骸继续作为战斗依赖，等待完整攻击者—弹道—目标场景合成。
- 引用同一素材且帧范围、步长、朝向和播放参数完全相同的事件会合并，并保留语义别名。

### 声音与文本

关系从 RULES/ART 的 `Voice*`、`Sound*`、武器报告和动画字段追踪到 SOUND/EVA、AUDIO.IDX/BAG、WAV/AUD 与 CSF。语音或音效分类基于引用证据和零售目录语义，不按 BAG/WAV/AUD 容器猜测。多人通讯与嘲讽从零售文件名中的国家代码关联到 RULES 的 `[Countries]` 顺序、名称和阵营。EVA 配置中的 `Allied`、`Russian`、`Yuri` 是按玩家阵营选择播报样本的字段，不是被介绍单位的归属；单位介绍依据事件前缀归入 EVA 或索菲亚，同事件重复引用的相同样本只形成一条语义关联，真正不同的录音仍分别保留。

官方 CSF、EVA 文本、固定来源的英文转录和本地校对补充按音频 stem 做字段级合并。接口独立保留 `original_text`（英文原文）、`localized_text`（游戏自带中文）与 `translated_text`（RA2 Explorer 校订译文），不会再用社区或编辑译文覆盖游戏文本。显示层默认译文优先，也允许用户改为游戏中文优先；首选来源缺失时回退到另一来源。CSF 提供的完整台词作为原生本地化基础；经实际零售音频核对的逐字稿与译文补充同名的单位名称标签，从而避免把 `CEVAU` / `CSOFU` 的名称误当成介绍内容，也避免资料片编号覆盖原版同名编号。经实际零售 BAG 音频审计确认的第三方转录错位使用版本化的文件名覆盖修正，重新同步参考表不会恢复错误映射。SOUND 注释中用于标记音效说明的首尾 `*` 在语义层统一清理并去重，不参与类型判断。没有可靠逐字稿时显示事件/任务说明或保持空值，不把文件名或单位名伪装成台词。音效以 SOUND/SOUNDMD 的事件名为主要分类证据，缩写样本名只在事件缺失时兜底；单位引用、武器引用等真实复用关系继续保留，系统提示、超级武器和界面音效则按事件语义显示子分组。

## 渲染与界面契约

- SHP、TMP 与 VXL 都是索引色资源。单位主体使用 `unit*.pal`，地块使用 `iso*.pal`，独立效果通常使用 `anim.pal`；剧场和 `AltPalette` 会改变选择。
- VXL 后端按 TS/RA2 法线、HVA 旋转与 Westwood VPL 查找最终颜色。前端使用无二次光照材质，避免把已着色结果再次照明。
- VXL 部件在统一世界坐标中应用 HVA；相机根据变换后的整体包围盒与当前容器比例自适应。鼠标旋转、平移和缩放不改变用户保存的默认预览角度。
- 建筑取景使用地基、主体、兼容的持续图层及 VXL 炮塔/炮管的可见并集；SHP 建筑与 VXL 炮塔分别使用自身的八向映射，再组合为同一预览。步兵卡片在完整保留轮廓的前提下使用更紧凑留白。SHP 动画保持稳定源画布坐标，播放时不逐帧重新自适应。
- 左栏是一棵“单位 / 声音 / 可选素材”语义树。默认 grid，list 在桌面使用双列；上下/左右详情布局、尺寸、选择和滚动位置按数据源、分类、条目、信息 tab 与布局分别持久化。切到未浏览条目或主动切换分类时同步回到对应区域顶部，返回已浏览上下文才恢复其自己的位置；820px 以下由页面承接详情滚动时，以新详情顶部作为锚点。
- 搜索框只保留“单位 / 声音”目标选择。单位和声音共用查询状态与补全，支持简繁、异体字等价、英文、全拼、首字母以及中文和拼音连续混合输入；长度足够的词允许一次相邻换位、增删或替换，以容忍“砲/炮”和轻微误输入，同时用严格长度边界避免无关泛匹配。单位建议复用卡片缩略图，语音和音效使用各自的图标与色彩。空输入聚焦时显示本机保存、可逐项删除或清空的搜索历史和最近访问；补全跳转会把目标补入当前分页、展开所属分组并在渲染后居中聚焦。当前浏览分类只影响结果排序权重，完整结果页的筛选与集合上方的正常浏览筛选彼此独立。
- 单位详情使用“声音 / 动画 / 数据”分区；动画按主体、建造和运行细分组同页展示。声音共用单一播放器，列表、详情和单位关联不会产生重复音轨。

强制 UI 约束集中在 `.agents/skills/must-follow-ui-design-rules/SKILL.md`。

## 缓存与性能

- Pages 把同类单位卡片缩略图合并成分类 WebP 图集；另为全部可渲染单位生成每格 36×36、按预览角度组织的全局搜索图集。搜索小图在发布阶段完成透明边界裁剪、等比缩放和居中，浏览器只做一次背景定位，不再逐项请求或运行时变换。建筑状态同样在发布阶段预合成为主体 WebP。本地版使用紧裁切补全图，普通卡片继续保留稳定构图；首屏稳定后由低优先级队列预取当前分类，新分类批次优先，但旧批次不会丢失。
- Pages HTML 预连接固定版本 jsDelivr，并提前获取启动清单、默认简体单位目录和默认角度搜索图集；启动清单、双语目录、卡片图集和搜索图集使用 CDN 优先、同源失败回退，模型、详情和声音仍由 Pages 按需提供。声音类型、用途和事件计数随启动清单返回，不为显示分类而下载完整声音目录。
- 实体、资产、元数据和关联请求共用有界 Promise 缓存；分类切换会恢复该分类最近查看项，首次进入则确定性选择当前排序第一项，并只预取相邻详情。
- 全局搜索的单位与声音请求独立完成并增量展示，较大的声音目录不会阻塞已经匹配到的单位补全。
- 已解码卡片在会话内复用，来源扫描修订写入 URL；回到已访问分类不重复请求，重扫不会复用旧图。
- 声音列表只预取前方少量条目；单位详情返回后优先预取每个关联事件的首条语音，再在后台补齐当前单位。聚焦会提升优先级，点击未完成预取的声音会取消重复请求并立即走浏览器流式播放；Blob LRU 同时受条目数与字节数约束。
- 交互模型只预测当前和相邻单位，并使用有界持久响应缓存与解析 LRU；Three.js 拆为稳定延迟 chunk，不阻塞普通卡片首屏。
- SHP 动画先解码首帧和下一帧，首帧就绪后才启动时间轴；切帧使用同坐标样式的显隐双缓冲，待实际显示的主体、组合层和特效层全部解码后再原子交换。新请求在渲染阶段立即使旧候选失效，快速拖动帧滑块也不会让过期帧短暂回写；整个序列继续使用固定 fit 边界。
- 这些策略自动生效，不作为用户设置暴露。性能验收应记录首屏、分类切换、回切请求、音频首播、模型首开、长任务和内存，而不是用“全部预载”掩盖瓶颈。

## API 边界

本地 OpenAPI 位于 `/api/docs`。主要资源：

- `/api/sources`、`/api/discovery`、`/api/sources/{id}/scan`：来源发现、导入与重扫；
- `/api/assets` 与 `/api/assets/{id}/*`：目录、元数据、文本、预览、媒体、模型、关联和原始导出；
- `/api/entities` 与 `/api/entities/{source}/{entity}/*`：单位搜索、详情、组合预览和模型；
- `/api/media`：语音/音效、事件分组、文本和关联；
- `/api/semantic/{source}/diagnostics`：实体、组件、本地化和依赖覆盖；
- `/api/player-colors`、`/api/palettes`、`/api/stats`：辅助目录。

本地服务只允许回环监听。写操作不对 Pages 静态版开放；浏览请求不会隐式同步网络参考数据。

## 发行与安全

PyInstaller one-folder 包只包含两个启动入口、共享 `_internal`、编译前端、公开参考数据、MIT 许可证和简短用户说明。发行审计拒绝源码、测试、开发文档、source map、本机路径、秘密文件和意外游戏可执行文件；第三方 `.dist-info` 的许可证告知文件例外保留。

`generic` 包不含游戏数据；`linked` 包只适合原电脑；`portable` 只有显式授权和 `--include-game-data` 才复制白名单格式。详细内容见 [发行说明](DISTRIBUTION.md) 与 [隐私说明](PRIVACY.md)。

## 已知限制

- 地图视图当前展示结构和对象布局，不是完整游戏渲染器。
- FNT 没有专用查看器，部分视频需要用户提供 FFmpeg。
- 完整战斗场景合成、Mod Profile 和持久后台任务队列尚未实现。
- 游戏配置不提供字幕的音频无法保证逐字文本；界面只展示有证据的说明。

这些限制应在对应能力实现后直接更新本节，不再维护独立的阶段计划文档。
